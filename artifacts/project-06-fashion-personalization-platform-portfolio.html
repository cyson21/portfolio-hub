01

해결한 문제

중복·실패 이벤트가 프로필과 추천 snapshot을 오염함

패션 커머스 추천은 브랜드, 카테고리, 태그, 사이즈, 가격대, 재고 같은 catalog feature와 사용자 행동 이벤트가 함께 반영되어야 합니다. 중복 이벤트나 처리 실패가 profile을 오염시키지 않도록 이벤트 안정성, batch snapshot, 관리자 리포트를 하나의 백엔드 흐름으로 분리했습니다.

검증 결과

  • EventProcessor 테스트가 동일 idempotency key를 한 번만 반영하고 3회 실패 뒤 DLQ로 격리합니다.
  • 추천 테스트가 6개 상품 fixture에서 브랜드·사이즈·가격·재고 조건을 deterministic ranking에 반영합니다.
  • Batch workflow 테스트가 active user별 snapshot을 2개 이상 만들고 stale snapshot 0을 확인합니다.
구현 결과

중복 이벤트를 한 번만 반영하고, 3회 실패를 DLQ로 격리하며 추천 snapshot과 freshness 지표를 생성합니다.

확인한 범위와 남은 경계

검증 구현은 인메모리 저장소를 사용하며 FastAPI는 선택 adapter입니다. PostgreSQL·SQS/EventBridge·S3·AWS 배포는 포함하지 않았습니다.
